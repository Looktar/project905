# 决策记录

已确认的立项决策见 `docs/kickoff-prompt.md`。以下为实现过程中的补充决策。

- **D-01（2026-10-31）v0 不用 Three.js/Vite/TS**：制作环境无法访问 npm，v0 用原生 WebGL2 + ES Modules 完成，零依赖、零构建，GitHub Pages 直接托管。下一阶段由 Claude Code 评估：继续原生（体积小、已可玩）还是迁移到规格中的 Three.js + Vite + TS。迁移属于大重构，需先与总决策确认。
- **D-02 地图西边多留约 170 米**：为把万锦市政厅包进来（它在 Warden 以西）。
- **D-03 GitHub Pages 用“从 main 分支根目录部署”**：无构建步骤，不需要 Actions；`.nojekyll` 关闭 Jekyll。若将来引入构建再改为 Actions。
- **D-04 人物用程序化分段小人**（大头、身体、四肢、帽子），不用骨骼蒙皮；车也是程序化几何体。
- **D-05 树用二十面体树冠**（低多边形风格 + 省顶点）。
- **D-06 开车撞普通车不算犯事**；撞警车、撞人、打人、抢车算犯事。
- **D-07 主角脱离战斗 5 秒后自动回血**（没有补给道具）。
- **D-08（2026-10-31）不迁移 Three.js，继续原生 WebGL2；只在开发阶段引入工具**：云端环境现在能连 npm，但迁移要重写渲染层（约 1–2 个工作周期），玩家感受不到区别，还会多 ~600KB 和构建步骤；当前 37 draw call、JS 156KB，性能有余量。Kenney 站点在云端被拦（403），GLB 素材仍需在电脑上下载，届时原生写最小 GLB 加载器即可。折中：`package.json` 只放开发依赖（ESLint、Vitest、Playwright），游戏本身仍零构建、GitHub Pages 直接托管（D-03 不变）。以后若要大量 GLB 模型、复杂后期，或代码超过约 8000 行，再重新评估。
- **D-09 不用 Prettier**：现有代码是紧凑写法，全量格式化会产生巨大 diff、淹没真实改动；用 ESLint 只查真问题（未定义变量、未使用变量等）。
- **D-10 v0.1 打磨里程碑并行开发**：项目经理（Claude）拆成 4 个工作包——工程底座（测试/CI）、红绿灯与车型、地标与街道道具、遮挡半透明与设置页——由子代理在独立 worktree 并行开发，项目经理负责集成、验收截图和 PR。
- **D-11 测试与 CI**：Vitest 单元测试 + 无头模拟（真 World/Game + 假渲染器/HUD + 固定随机种子，`SIM_SEED=n` 可换种子）+ Playwright 冒烟测试（SwiftShader；桌面 1440×900、手机横屏 844×390、手机竖屏 390×844，控制台报错即失败，三张截图在 `test-results/smoke/`）。GitHub Actions 只做检查（lint、单元测试、地图可复现、冒烟），不负责部署（D-03 不变）。
- **D-12 强制横屏坐标换算放进纯函数模块 `js/orient.js`**：`CFG.input.rotateDir` 1 = 顺时针（默认，iPhone 刘海在左）/ -1 = 逆时针；安全区用 CSS 变量 `--sa-l/r/t/b`，按旋转方向换算到对应的物理边。
- **D-13 ESLint 只拦真错误**：未使用变量、常量条件只给警告。
- **D-14 Playwright 固定 1.63.0**，与云端预装浏览器 chromium-1243 匹配；本地不要运行 `playwright install`，CI 里用 `npx playwright install --with-deps chromium`。
- **D-15 已知 bug 先写成 `it.fails` 测试**，修好后测试会提示，再改回 `it`（被抓重生距离 bug 就是这样发现并修掉的）。
- **D-16 遮挡处理**：挡住主角的 OSM 建筑淡出成半透明（先写深度、再混合，只画最前面一层，看起来像一块干净的玻璃）；被房子、树等挡住时，主角显示青色 X 光轮廓（模板缓冲保证每个像素只染一次）。主角的部件排在每个批次最前面，轮廓只画前 k 个实例，不需要额外的批次。
- **D-17 画质拆成三项**：阴影、清晰度（像素比：手机 1 / 1.25 / 1.5，规格上限 1.5；电脑 1 / 1.5 / 2）、微缩景深。帧率连续 4 秒低于 26 时自动降一档，顺序是：景深 → 清晰度 高→标准 → 阴影 → 省电；玩家手动改过就不再自动降。`?noauto=1` 固定画质，用于截图和测试。
- **D-18 微缩景深（规格 4 节）**：电脑默认开、手机默认关；屏幕空间 16 次采样的模糊，主角所在的横带保持清晰。
- **D-19 设置和制作人员面板打开时游戏暂停并静音**；电脑上按 Esc 开关设置。
- **D-20 路人过马路（规格 2.2）**：偶尔在双向路上掉头，也就是走到对面人行道；过马路前先看车，迎面来的车到达时间要比过街时间多 1.5 秒以上才走，最多等 12 秒。路口转弯、尽头掉头也改成走过去，不再瞬移。
- **D-21 `?bench=1` 基准测试模式（规格 7 节）**：在出生点预热 5 秒、测 15 秒，显示平均帧率、最差 1%、draw call、CPU 耗时、实体数和画质；总决策在手机上截图发回即可记录到 PROGRESS。
- **D-22 被抓后重生**：吸附到最近的路面点后复核 150–300 米，避开水和铁轨，并尽量远离步行警察和警车。
- **D-23 Unionville 老街**：OSM 的历史街区以前被画成停车场，现在两侧改为彩色店面（26 间：山墙或平顶、雨棚、橱窗），屋顶立“Unionville 老街 Main St”招牌。
- **D-24 Toogood Pond 凉亭**：OSM 点离水边约 80 米（真实距离），挪到离岸约 6 米处；观景木码头放在 OSM 观景台点，可以走上去。
- **D-25 Downtown Markham**：OSM 已有的高楼太稀，在停车场或现有高楼旁补 8 栋程序化塔楼（26–46 米），立“Downtown Markham”招牌；影院恶搞名“Cineplax 影城”，屋顶放红白条纹爆米花桶。
- **D-26 Tim Hortz 放置**：优先用店所在的小建筑（≤450 m²），否则就近找空地新建小店，并避开被高楼挡住的位置。由 2 家增加到 5 家。
- **D-27 Viva 车站**：OSM 没有快速公交道上的站台点，所以在快速公交道沿线的主干道路口放 5 个中央站台（站距 ≥110 米，0.6 米宽，不挡公交道）；Hwy 7 × Main St 的两个真实站点放路边候车亭。没有任何文字或标志。
- **D-28 街道道具全部烘焙进区块网格**（消防栓 546 个、井盖 799 个、公交站 10 个，不增加 draw call）；路灯、停车位和停着的车不再放在公交道上。
- **D-29 红绿灯在加载时由路网计算（`js/signals.js`）**，不改 `build_map.py`、不需要重建地图。信号路口 = 至少 2 条不同名的主干道（cls ≤ 2）相交；25 米内的路口节点合并成一个路口；少于 3 条腿或只有一个方向轴的不设灯（共 93 个）。
- **D-30 相位**：东西绿 9 秒 → 黄 2 秒 → 全红 2 秒 → 南北绿 9 秒 → 黄 2 秒 → 全红 2 秒，各路口按黄金分割固定错开。黄灯时能以 4.5 m/s² 舒适刹停就停，否则通过；红灯时能以 9 m/s² 刹停就停。追捕中的警车和主角不看灯；路人暂时不看灯。
- **D-31 灯柱立在进口道右侧人行道转角**，横臂伸到车道上方，灯头两面都显示（固定镜头总能看到）；灯柱、灯头和白色停止线烘焙进区块网格，只有灯泡是一个动态批次（+2 draw call，只画主角 165 米内的路口）。
- **D-32 车流**：提前一条路段选好下一条路，好看到前方的停止线和前车；停车时车距 6.8 米，行驶时再加 0.5 秒车头时距；汇入同一路段时离汇合点远的车让行；分隔路分叉处不掉头。防死锁：卡住 25 秒的车在 4 秒内无视信号灯和让行，但仍和前车保持距离、不撞人。主角挡路时车会一直等着按喇叭，不会碾过去。
- **D-33 车型**：轿车 50%、SUV 25%、面包车 10%、出租车 15%；面包车最高速 ×0.88、加速 ×0.8，SUV 最高速 ×0.97。新车型复用轿车的实例批次（不增加 draw call）；停车场里的静态车仍只有轿车。
- **D-34 修复既有 bug**：被打倒的路人以前永远爬不起来（`flee()` 不处理倒地状态），倒在路口的人会永久堵住车流。
- **D-35 警察人数上限 8（规格 6.4）**：步行警察 + 警车里的警察一起算，到上限就不再派巡逻、警车和增援（`CFG.police.max`）。
