# 美术规范（Art Bible）· Project 905

> 判断“像不像我们的游戏”的依据。验收基准仍是 `docs/concept.jpg`。引入外部模型（Polyfork 等）前先对照本文件。
> 写法参考了 Claude-Code-Game-Studios 的 art-bible 流程和 awesome-gamedev-agent-skills 的 create-game-assets 技能（见 D-49）。

## 1. 一句话
**明亮、圆润的玩具城微缩沙盘，熟人一眼认出是万锦。** 拿不准时：选更圆、更亮、更好认的方案。

三条原则：
1. **好认优先于真实**：地标靠夸张的屋顶道具和谐音招牌认出来，建筑细节可以省。
2. **玩具感**：圆角、饱和色、柔和阴影、没有脏旧和写实贴图。
3. **手机上要看得清**：镜头在 70 米外俯视，小于 0.5 米的细节基本看不见，不值得花顶点。

## 2. 气氛与光照
- 固定白天晴天；暖白主光从东南方打下，柔和阴影，冷色环境光（`renderer.js`）。
- 远处轻微雾化成天空色 `#a9b8cf`；电脑上开微缩景深。
- 被追捕时不改光照，靠警笛、闪灯和横幅制造紧张感。

## 3. 形状语言
- 圆角盒是基本单位（`rbox`）；树冠是二十面体，低多边形、平面着色。
- 人物：Q 版，头身比约 1:1.3，大头、短四肢、分段身体，没有骨骼。
- 车辆：短而胖的玩具车，轮子略夸张。
- 地标：屋顶放比例夸张的大道具（奶茶、购物袋、甜甜圈、爆米花桶）。

## 4. 色彩
| 用途 | 颜色 |
|---|---|
| 草地 / 公园 | `#9fd067` / `#b3db6f` |
| 路面 / 人行道 / 停车场 | `#5b6782` / `#dde1e8` / `#cdd2dc` |
| 水 | `#5fb3e6` |
| 快速公交道 | `#b4625a` |
| 天空 / 雾 | `#a9b8cf` |
| 界面主色（按钮、强调） | `#ff6b4a`、`#3fa7ff`、`#56c26b`，文字 `#2d3a55` |

- 车、衣服、房子从调色板里随机取色，饱和度高、明度中高；避免纯黑和纯白的大面积色块。
- 警察统一深蓝 `#1e3a8a`；红色和蓝色闪灯只给警车。
- 外来模型要把颜色**重映射到上面这些色系**，不能直接用原模型的写实或灰暗配色。

## 5. 人物
- 各族裔混合，贴近万锦实际：华裔、南亚裔（约 35%，有 kurta、dastar、dupatta 等）、白人、黑人等，肤色和发色各有调色板。
- 不做口音、刻板台词或带歧视的造型；性格（胆小、暴躁、高手）与族裔无关、随机分配。
- 卡通暴力：被打会弹一下、冒星星，没有血。

## 6. 环境
- 路网、街区、地标都来自真实的 OpenStreetMap，按 40% 压缩。
- 住宅区是程序生成的彩色小房子；商业建筑保留真实轮廓并略作放大。
- 招牌全部面向镜头，必须用谐音名；路牌是绿底白字。
- 道具密度：主干道上有路灯、消防栓、井盖、红绿灯、公交站；居民区以房子和树为主。

## 7. 外来模型（Polyfork / CC0）入库标准
1. **先做样板**：每一类模型（车、树、路灯……）先换 1 个，截桌面和手机图给总决策确认，再批量替换。
2. **风格检查**：低多边形、平面或顶点色、圆润；不能依赖 PBR 贴图或法线贴图（渲染器只用顶点色，`js/glb.js` 会按 UV 在调色板贴图上取色）。
3. **尺寸和朝向**：游戏单位是米。轿车长约 4.4 米、宽 2.1 米；人高约 2.6 米；行道树高 4–5 米。原点放在地面中心，车头朝 +z。
4. **三角形预算**（每个实例）：车 ≤ 1500，树 ≤ 400，街道道具 ≤ 300，人物 ≤ 1000，地标道具 ≤ 4000。
5. **文件**：放在 `assets/models/<类别>/`，GLB 单个 ≤ 150 KB、全部 ≤ 3 MB；登记到 `assets/asset-manifest.json` 和 `CREDITS.md`（来源网址、作者、许可）。
6. **不能增加 draw call**：同一类模型共用一个实例批次，或烘焙进区块网格。

## 8. 性能预算（按 performance-optimization 技能“先测量、定预算”的做法）
| 项目 | 预算 | 现状（2026-11） |
|---|---|---|
| 手机帧率（iPhone 12 / Pixel 6） | ≥ 30 fps | 待总决策用 `?bench=1` 实测 |
| 电脑帧率 | 60 fps | — |
| draw call（出生点满员） | 手机 ≤ 150 | 约 70 |
| 每帧 CPU | 手机 ≤ 8 ms | 无头软件渲染约 4 ms |
| 首次下载 | < 15 MB | 约 1.3 MB（地图 0.95 MB） |
| 招牌图集 | ≤ 2 页 2048 | 1 页 |

超预算先用 `?bench=1` 和 `?debug=1` 测量，找出瓶颈再改，并把前后数字写进 PROGRESS。

## 9. 手感（按 game-feel 技能）
- 反馈分三级（`CFG.feel`）：小（出拳打中路人）、中（打警察、被打、撞车）、大（被打倒、重撞）。每级配不同的镜头震动和顿帧时长。
- 镜头震动用平滑衰减的创伤值，不用每帧随机抖动；只晃镜头，不动角色。设置里可以关掉震动。
- 被打的人会压扁再回弹一下，然后恢复原状；反馈要短，不挡操作。
